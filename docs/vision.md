# 产品愿景

## 一句话定义

Kiseki 是一个本地优先、AI 辅助的个人轨迹记录与决策系统：它把每天的经历转化为可检查的证据、评分向量和长期路线变化。

> 让每天的证据，显现长期的轨迹。

## 要解决的问题

人在进行职业、生活和关系选择时，常常同时面对三个困难：

- 每天的感受真实但容易被近期情绪放大。
- 长期收益存在，但很难从零散事件中观察出来。
- 不同选择的机会窗口、风险和代价并不在同一个尺度上。

普通日记擅长保存叙述，却不擅长比较趋势；普通任务管理器擅长记录完成情况，却不理解体验和选择。Kiseki 希望在两者之间建立一层可解释的分析系统。

## 产品承诺

Kiseki 不宣称给出人生的客观答案。它提供的是一套可回看、可修正的观察框架：

1. 保存未经加工的原始记录。
2. 从记录中提取事实、感受和影响证据。
3. 给出带理由和置信度的候选评分。
4. 允许用户根据自己的感受调整结果。
5. 将每日变化累积为长期趋势，而不是用单日分数替代判断。

## 目标用户

第一位目标用户是项目作者本人，尤其适用于：

- 同时考虑多条职业或生活路线；
- 习惯深入思考，但容易被大量可能性消耗；
- 愿意持续记录，希望用长期证据校正直觉；
- 重视隐私，不希望原始日记默认成为云端公共数据。

## 核心原则

### 原文优先

模型输出不能覆盖或替代原始记录。任何分数都应能回到当天的输入查看。

### 证据先于分数

模型首先提取证据，再产生候选分数。没有证据的维度应标记为未知，而不是自动记为中性分。

### 体验与积累分离

“今天过得如何”和“今天为某条路线积累了什么”是两个问题。高成长的一天可能非常疲惫，轻松的一天也可能没有路线增量。

### 可解释、可修正

每个评分都应包含理由、证据和置信度。用户修正不是异常，而是系统校准的一部分。

### 本地优先

原始记录和分析历史默认保存在本地。调用外部模型时，应明确哪些内容会被发送到第三方服务。

## 长期成功标准

Kiseki 的成功不以“模型打分看起来聪明”为标准，而以以下结果衡量：

- 用户能够连续记录，而不会被复杂表单阻碍。
- 同一评分规则在数周内保持足够稳定和可比较。
- 用户能够解释某条曲线为何变化，而不是只看到数字。
- 系统能帮助发现反复出现的模式、路线机会和隐性成本。
- 数据可以导出、重算和迁移，不被单一模型或服务锁定。

## 非目标

- 不进行心理健康、医疗或人格诊断。
- 不把百分制包装成客观真理。
- 不替用户自动做出重大人生决定。
- 不在最简原型阶段构建社交网络、排行榜或游戏化激励。

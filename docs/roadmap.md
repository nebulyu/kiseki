# 项目路线图

路线图服务于个人使用，不设置严格工程门槛。每一步都以“是否已经产生真实价值”为判断依据。

## Phase 0：定义与准备

状态：进行中

- 明确项目目标和评分维度。
- 准备输入、输出和提示词模板。
- 安装 uv。
- 初始化简单 Python 项目。

完成后直接进入实现，不继续扩写架构。

## Phase 1：可用的 CLI 原型

- `add`：输入感想、调用模型、保存结果。
- `list`：快速查看历史记录。
- `show`：查看原文和完整分析。
- SQLite 使用一张 `daily_records` 表。
- 模型调用直接写成一个清楚的函数。

当它能够保存并展示几条真实日记时，就开始使用，而不是继续补充测试和通用能力。

## Phase 2：个人试用与评分调整

- 连续使用一到两周。
- 记录哪些分数符合直觉，哪些解释明显不对。
- 直接调整提示词、维度定义和输出格式。
- 观察自己是否愿意每天打开它。

这个阶段的核心产物是个人反馈，不是测试覆盖率或评估平台。

## Phase 3：长期路线

只有每日评分确实有用后，才加入：

- 路线定义和维度权重。
- 每条路线的当日变化。
- 简单的长期趋势计算。
- 路线之间的对比。

第一版路线规则仍可直接写在配置文件里，不提前构建规则引擎。

## Phase 4：更方便的界面

当 CLI 开始妨碍日常使用时，再选择合适的本地界面：

- 输入每日感想。
- 查看评分和解释。
- 浏览历史和趋势曲线。
- 调整路线配置。

具体采用 React、FastAPI 或桌面封装，在那时根据真实需求决定。

## 暂不考虑

- 多人协作和社交功能。
- 云同步与账号系统。
- 企业级权限和审计。
- 微服务、消息队列和高可用设计。
- 面向公众的统一人生评分标准。

# 功能范围

本文区分 Kiseki 的长期方向和当前要快速做出的个人原型。第一版只实现最短使用闭环。

## 长期功能方向

### 每日记录

- 输入自由文本形式的感想、事件和观察。
- 记录日期、标签和可选上下文。
- 查看和编辑过去的记录。

### AI 分析

- 提取事实、情绪、收获和成本。
- 输出整体体验分和基础属性向量。
- 给出简短摘要、评分依据和置信度。
- 允许用户接受、修正或否决模型给出的候选评分。

### 长期路线

- 创建职业或生活路线。
- 为不同路线设置关注维度和特殊因素。
- 观察路线的每日变化与长期曲线。
- 比较不同选择的收益、成本和机会窗口。

### 复盘

- 查看周、月和长期趋势。
- 发现持续增长或持续消耗的模式。
- 根据真实使用逐步调整评分规则。

### 数据

- 默认保存在本地。
- 后续支持导出和备份。
- 明确外部模型会接触哪些文本。

## 当前最简原型

第一版只完成：

1. 在终端输入日期和当天感想，或读取 UTF-8 的 `.md`/`.txt` 文件。
2. 将原文写入 SQLite 的 `daily_records`。
3. 调用一个已经选定的模型 API。
4. 获取整体分、六维向量、摘要、依据和置信度。
5. 使用 Pydantic 把 JSON 解析为固定结构。
6. 将结果更新到同一条记录并在终端展示。
7. 使用 `review <id>` 在本地接受、修正或否决已有分析，人工结果与 AI 原始 JSON 分开保存。
8. 统一计算最终有效分数：人工覆盖优先，否决后无有效分数，过期 Review 不套用到新分析。
9. 可以列出历史记录并查看 AI 分数、最终分数、Review 状态和某条详情。

## 第一版不做

- 图形界面和账号系统。
- 多设备同步。
- 多模型 Provider 抽象。
- 分析历史、Review 历史、迁移框架和自动重算；`analysis_revision` 只是当前分析版本计数。
- 自动重试、任务队列和复杂错误状态。
- 完整单元测试套件和覆盖率要求。
- 路线计算引擎。
- 本地大模型部署。
- 校准汇总、自动训练和自动修改提示词。

## 完成判断

第一版达到以下状态即可开始真实使用：

- 能输入一段日记并看到模型评分。
- 关闭程序后，记录仍可从 SQLite 读取。
- `list` 和 `show` 可以查看已有内容。
- `review` 不调用模型，也不修改原文或 AI 原始分析。
- `accepted` 使用 AI 分数，`adjusted` 应用人工覆盖，`rejected` 没有最终分数。
- 分析版本变化后旧 Review 显示为 `stale`，旧覆盖不会套用到当前分析。
- API Key 没有被写进源码或数据库。
- 人工试用几条记录后，输出大体符合个人直觉。

除此之外的问题先记录，不在第一版集中补齐。

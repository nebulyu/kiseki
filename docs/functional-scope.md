# 功能范围

本文区分 Kiseki 的长期方向、现有日记原型和下一步路线 MVP。路线开发与日常评分校准并行，具体规格集中维护在 [长期目标与路线 MVP](long-term-routes.md)。

## 长期功能方向

### 每日记录

- 输入自由文本形式的感想、事件和观察。
- 记录日期、标签和可选上下文。
- 查看和编辑过去的记录。

### AI 分析

- 提取事实、情绪、收获和成本。
- 输出整体体验分和基础属性向量。
- 给出简短摘要、评分依据和置信度。
- 允许用户接受、修正或否决模型给出的候选评分。

### 长期路线

- 区分期望结果的目标与实现方式的路线，一个目标允许关联多条路线。
- 为不同路线定义关注维度、推动信号、成本、关键假设和判断条件。
- 从原文提取路线证据，区分计划、尝试、成果与阻碍，并允许用户确认。
- 分别观察当日影响、阶段成果、可复用积累和持续消耗。
- 后续比较不同选择的收益、成本和机会窗口，不把单一分数作为自动决策依据。

### 复盘

- 查看周、月和长期趋势。
- 发现持续增长或持续消耗的模式。
- 根据真实使用逐步调整评分规则。

### 数据

- 默认保存在本地。
- 后续支持导出和备份。
- 明确外部模型会接触哪些文本。

## 当前日记原型

当前已实现的范围：

1. 在终端输入日期和当天感想，或读取 UTF-8 的 `.md`/`.txt` 文件。
2. 将原文写入 SQLite 的 `daily_records`。
3. 调用一个已经选定的模型 API。
4. 获取整体分、六维向量、摘要、依据和置信度。
5. 使用 Pydantic 把 JSON 解析为固定结构。
6. 将结果更新到同一条记录并在终端展示。
7. 使用 `review <id>` 在本地接受、修正或否决已有分析，人工结果与 AI 原始 JSON 分开保存。
8. 统一计算最终有效分数：人工覆盖优先，否决后无有效分数，过期 Review 不套用到新分析。
9. 可以列出历史记录并查看 AI 分数、最终分数、Review 状态和某条详情。
10. 使用 `analyze <id>` 对已有记录原地分析或重试；已有成功结果时必须明确确认才重新分析。
11. 在同步分析期间显示模型、成功或失败前的耗时，并使用 120 秒请求超时。
12. 只有 `add` 和 `analyze` 会向外部模型发送记录日期与原文；`review`、`list` 和 `show` 只访问本地数据。

## 下一步路线 MVP（尚未实现）

1. 从个人 YAML 配置读取目标与路线，查看关联目标和信号规则。
2. 显式选择一条日记和一条路线，独立调用模型分析相关证据。
3. 按匹配信号计算 `-5` 到 `5` 的候选当日影响，无证据保持 `null`。
4. 独立保存路线结果、配置快照与路线 Review，不覆盖每日评分和 Review。
5. 支持确认、修正或否决，以及按日期查看路线证据与版本差异。

路线配置样例仅用于设计，当前程序不会加载。路线分析不依赖每日评分先稳定，也不要求已积累固定数量的 Review。原型仍采用普通函数、本地 SQLite 和一个已配置模型，不建设通用规则引擎。

## 当前未提供及本轮路线 MVP 不做

- 图形界面和账号系统。
- 多设备同步。
- 多模型 Provider 抽象。
- 分析历史、Review 历史、迁移框架和批量或自动重算；`analysis_revision` 只是当前分析版本计数。
- 自动重试、任务队列和复杂错误状态。
- 完整单元测试套件和覆盖率要求。
- 通用路线规则引擎、长期总分、自动排名与成功概率。
- 自动完成里程碑、资产库、机会窗口衰减和跨记录成果去重。
- 本地大模型部署。
- 校准汇总、自动训练和自动修改提示词。

## 完成判断

当前日记原型按以下行为判断可用；路线功能单独按规格的分步交付标准验收：

- 能输入一段日记并看到模型评分。
- 关闭程序后，记录仍可从 SQLite 读取。
- `list` 和 `show` 可以查看已有内容。
- `review` 不调用模型，也不修改原文或 AI 原始分析。
- `accepted` 使用 AI 分数，`adjusted` 应用人工覆盖，`rejected` 没有最终分数。
- 分析版本变化后旧 Review 显示为 `stale`，旧覆盖不会套用到当前分析。
- 未分析或失败记录可以通过 `analyze <id>` 恢复，且不会创建重复日记。
- 重新分析成功会增加 revision 并保留旧 Review；重新分析失败会保留旧成功分析、revision 和 Review。
- API Key 没有被写进源码或数据库。
- 人工试用几条记录后，输出大体符合个人直觉。

除此之外的问题先记录，不在第一版集中补齐。

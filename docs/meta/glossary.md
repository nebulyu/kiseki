# 核心术语

## Entry / 原始记录

用户针对某个日期输入的原始文字。模型输出不得覆盖它。

## Analysis Result / 分析结果

模型针对一条 Entry 返回的结构化评分、摘要和依据。第一版直接保存在对应的 `daily_records` 中。

## Evidence / 证据

能够支撑某项判断的原文片段，以及它的影响方向、强度、所属维度和置信度。

## Overall Score / 整体体验分

对“这一天整体过得如何”的 0 到 100 候选评分。它不等于成长总量，也不等于路线价值。

## Dimension Vector / 基础属性向量

由技术成长、人际资本、信息增益、社会参与、身心状态和自主感组成的每日结构化结果。

## Candidate Score / 候选评分

模型根据当前规则给出的建议值。它可以被用户修正，也可能在未来被确定性评分器替代。

## User Review / 人工复核

用户对某次 AI 分析的独立判断。持久化状态包括 `accepted`、`adjusted` 和 `rejected`；它不覆盖原文或 AI 原始分析。

## Effective Score / 最终有效分数

当前 AI 候选分与有效 Review 合成后的读取结果。人工覆盖优先，rejected 没有有效分数，stale Review 的旧覆盖不参与计算。

## Stale Review / 过期复核

Review 保存的分析 revision、模型或提示词版本与当前分析不一致时的派生状态。旧 Review 继续保留供查看，但需要重新确认后才能再次影响有效分数。

## Confidence / 置信度

原文对某项判断的支持程度，范围为 0 到 1。置信度低不等于分数低。

## Route / 路线

为一个目标采取的实现方式，例如通过工程项目积累能力或通过研究实验探索方向。一个目标可以关联多条路线；第一版每条路线只关联一个目标。

## Goal / 目标

希望达到、维持或探索的状态，包含个人理由、判断标准和可选时间范围。目标说明期望结果，路线说明实现方式，二者不是同一对象。

## Milestone / 里程碑

可由用户确认的阶段成果。路线 MVP 先把它写成目标判断标准，不自动更新完成状态。

## Asset / 积累

能够继续使用的成果、经验或资源。已经形成的积累不因某一天体验不好而自动消失；资产库与跨记录成果去重属于后续功能。

## Route Signal / 路线信号

路线配置中有明确匹配条件和影响分值的推动因素或成本。模型从原文识别匹配证据，本地规则计算候选影响；计划不应被匹配为完成成果。

## Route Delta / 路线当日增量

一条日记中路线证据按规则映射出的候选当日影响，范围为 -5 到 5 或 null。无证据/无法判断保持 null，有依据的正负信号相抵可以为 0。它不等于目标完成度，也不代表长期成果数量。

## Route Value / 路线状态值

旧模板使用的单一长期状态数值概念。本次路线 MVP 暂不实现，不采用“初始 50 分 + 每日增量”的累计方法；后续优先分别呈现进展、积累、成本和不确定性。

## Route Review / 路线人工复核

用户对特定路线分析的独立确认，绑定其分析 revision。它不继承每日 Review，不覆盖模型证据，也不自动完成里程碑。功能尚未实现，详见 [路线规格](../long-term-routes.md)。

## Outdated Route Analysis / 口径已变化的路线分析

当前目标/路线配置与分析所用快照不一致时的计划状态。旧结果仍可查看，但不作为当前配置下的有效结果，需要明确重分析；它与表示人工复核对应旧分析 revision 的 stale 分开显示。
